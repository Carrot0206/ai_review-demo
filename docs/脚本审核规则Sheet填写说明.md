# 脚本审核规则 Sheet 填写说明（重点：`operator` 和 `参数(JSON)`）

本文用于指导业务人员把已有审查规则填写到上传规则 Excel 的 `脚本审核规则` sheet，并在网页中上传、启用和执行审核。

对已有规则表而言，`operator` 和 `参数(JSON)` 是为“脚本审核”新增的两列：原来的业务规则描述了“应当如何”，这两列把它翻译成系统可以确定性执行的“如何检查”。本文重点说明这两列的填写方法。

适用对象：需要把可以明确、稳定判断的规则配置为脚本审核规则的人员，例如必填、枚举、日期格式、数值精度、字段比较、材料必交等规则。

> 不确定、依赖复杂业务语义、版式位置、图片内容、外部系统数据或人工判断的规则，建议填写到 `AI审核规则` sheet，不要强行写成脚本规则。

## 1. 使用前准备

请使用系统提供的空白模板：[上传规则Excel空白模板.xlsx](上传规则Excel空白模板.xlsx)。模板包含：

- `脚本审核规则`：填写本说明中的脚本规则；
- `AI审核规则`：填写需要 AI 语义判断的规则。

不要修改 sheet 名称，也不要删除脚本 sheet 中的必填列表头：`规则ID`、`具体规则`、`operator`。

## 核心：如何填写 `operator` 和 `参数(JSON)`

### 两列分别解决什么问题

| 列名 | 作用 | 填写时要回答的问题 |
| --- | --- | --- |
| `operator` | 选择检查动作。 | 这条规则是检查必填、枚举、长度、日期、数值比较，还是材料是否提交？ |
| `参数(JSON)` | 提供检查动作所需的具体条件。 | 允许哪些值、最大长度是多少、与哪个字段比较、触发条件是什么？ |

可以把一条业务规则拆成下面的句式：

```text
检查【字段路径】的值，使用【operator】；具体限制写在【参数(JSON)】中。
```

例如，业务规则“是否涉及关联交易只能填是或否”：

| 字段路径 | operator | 参数(JSON) |
| --- | --- | --- |
| `产品基本信息.是否涉及关联交易` | `enum` | `{"values":["是","否"]}` |

其中：`enum` 表示“枚举值检查”，`values` 表示“允许填写的全部值”。

### 先按业务规则选择 operator

| 原有规则的表达方式 | 应填写的 operator | `参数(JSON)` 是否必须 | 参数示例 |
| --- | --- | --- | --- |
| “XX 为必填项” | `required` | 否，填 `{}` | `{}` |
| “XX 只能为 A、B、C” | `enum` | 是 | `{"values":["A","B","C"]}` |
| “B 必须属于 A 对应的值” | `dependent_enum` | 是 | `{"parent_field":"A","child_field":"B","mapping":{"A1":["B1"]}}` |
| “XX 不超过 50 个字符” | `max_length` | 是 | `{"max_length":50}` |
| “XX 为数值，最多 2 位小数” | `number_precision` | 建议填写 | `{"scale":2}` |
| “XX 应为 YYYY-MM-DD” | `date_format` | 否，填 `{}` | `{}` |
| “XX 不早于当天，且不晚于一年后” | `date_range` | 是 | `{"min":"today","max_days":365}` |
| “XX 应符合固定编码格式” | `regex_match` | 是 | `{"pattern":"[A-Z]{2}\\d{6}"}` |
| “序号应从 1 连续递增” | `sequence_contiguous` | 否，填 `{}` | `{}` |
| “A 不得大于 B” | `compare_fields` | 是 | `{"right_field":"B"}` |
| “与上次登记模板相同” | `cross_template_equal` | 建议填写 | `{"current_field":"A","baseline_field":"A"}` |
| “当 A=是时，B 必填/符合条件” | `conditional_compare` | 是 | 见下方条件规则示例 |
| “必须提交某材料” | `material_required` | 建议填写 | `{"material_label":"信托合同"}` |
| “当 A=是时，必须提交某材料” | `conditional_material_required` | 建议填写 | `{"material_label":"关联交易说明"}` |

### 参数(JSON)的格式规则

1. 必须是 JSON 对象，即以 `{` 开始、以 `}` 结束。
2. 键名和字符串必须使用英文双引号，例如 `"values"`、`"是"`。
3. 数值不要加引号，例如 `{"max_length":50}`；不要写成 `{"max_length":"50"}`。
4. 多个允许值要使用数组，例如 `{"values":["是","否"]}`。
5. 没有参数时统一填 `{}`；不要填“无”“-”或自然语言说明。

正确：

```json
{"right_field":"发行规模"}
```

错误：

```text
比较字段=发行规模
```

```json
["是","否"]
```

### 不完整参数会发生什么

| 情况 | 实际结果 |
| --- | --- |
| `enum` 未填 `values` | 可以上传，但规则会跳过并记录配置告警，不会转入 AI 兜底。 |
| `dependent_enum` 参数不完整 | 上传失败，需补齐父字段、子字段和映射表。 |
| `max_length` 未填 `max_length` | 可以上传，但不会进行长度限制。 |
| `regex_match` 未填 `pattern` | 可以上传，但不会进行正则校验。 |
| `compare_fields` 未填 `right_field` | 脚本无法执行，转 AI 兜底。 |
| `conditional_compare` 未填完整 `target` | 脚本无法可靠执行，转 AI 兜底。 |
| 填写未支持的 operator | 不按脚本执行，转 AI 兜底。 |

下文第 6 节列出了每个 operator 的完整参数写法和执行边界；填写人员无需再查阅其他 operator 文档。

## 2. 最小可用的一条规则

下面是一条“产品名称必填”的最小可用规则。填写在 `脚本审核规则` sheet 的第二行即可：

| 规则ID | 规则名称/要素名 | 字段路径 | 具体规则 | operator | 参数(JSON) |
| --- | --- | --- | --- | --- | --- |
| `USER-INITIAL-SCRIPT-001` | 产品名称 | `产品基本信息.产品名称` | 产品名称为必填项。 | `required` | `{}` |

这 6 列中，导入强制要求的是 `规则ID`、`具体规则`、`operator`。但字段类规则如果缺少 `字段路径`，系统通常无法准确找到被审核字段，因此实际使用时应视为必填。

## 3. 各列如何填写

### 3.1 必填列

| 列名 | 填写要求 | 示例 |
| --- | --- | --- |
| `规则ID` | 每条规则一个唯一编号。建议使用 `USER-流程-SCRIPT-流水号`，避免与内置规则重名。 | `USER-INITIAL-SCRIPT-001` |
| `具体规则` | 用完整中文描述审核要求，作为审核结果的规则依据。 | `产品名称为必填项，不得为空。` |
| `operator` | 从模板下拉列表选择支持的英文小写操作符。 | `required` |

`规则ID` 在同一上传文件中不能重复，也不能在 AI sheet 和脚本 sheet 中重复。当前默认会同时使用内置规则，建议避免使用内置规则常见的编号前缀，例如 `INITIAL-`、`PREG-`。

### 3.2 直接影响审核的列

| 列名 | 何时填写 | 填写要求和示例 |
| --- | --- | --- |
| `字段路径` | 所有字段类规则 | 填写“表名.字段名”，例如 `交易结构.发行规模`。应与申报模板中的实际表名、字段名一致。 |
| `要素分类/表名` | 表级规则或字段路径不便填写时 | 填写规则所属表名，例如 `关联交易信息`。表级必填可填此列，并在 `规则对象` 填 `表`。 |
| `规则名称/要素名` | 建议所有规则填写 | 用于问题标题；材料类规则未填 `material_label` 时，也会用它作为材料名称。 |
| `参数(JSON)` | 大多数 operator | 填写合法 JSON 对象，决定枚举值、长度、比较字段等具体条件。 |
| `触发条件` | 条件规则 | 简单条件写成 `字段名=期望值`，例如 `是否涉及关联交易=是`。留空表示始终执行。 |
| `启用状态` | 需要暂不执行的规则 | 留空默认启用；填写 `否`、`false` 或 `0` 时不执行。 |

### 3.3 用于结果展示和追溯的列

| 列名 | 用途 | 建议 |
| --- | --- | --- |
| `审查依据` | 在审核结果中展示依据。 | 填写法规、制度、填表说明或内部口径。 |
| `审查维度` | 对规则做业务归类。 | 可填写“登记必填要素”“跨材料数据逻辑”等；不决定 AI 或脚本方式。 |
| `规则类型` | 标注规则特性。 | 版式、显著位置等不适合脚本的规则不要放入本 sheet。 |
| `适用材料` | 描述规则相关材料。 | 多个材料可用顿号、逗号、分号、斜杠或换行分隔。当前主要用于 AI 审核的材料裁剪。 |
| `规则对象` | 标注审核对象或问题类别。 | 表级必填规则填写 `表`；其他情况可按业务需要填写。 |
| `比对方式` | 补充审核方式说明。 | 例如“必填校验”“枚举值校验”。 |
| `AI审核重点` | 规则转 AI 兜底时的补充提示。 | 简明说明需要核查的事实或关系。 |
| `风险等级` | 标识风险等级。 | 包含“高”识别为高风险，包含“低”识别为低风险，其余为中风险。 |
| `来源sheet`、`来源行` | 追溯原始规则来源。 | 从旧规则表整理时填写；手工新建可留空。 |

## 4. 常用规则的填写示例

### 4.1 字段必填

| 字段路径 | operator | 参数(JSON) | 具体规则 |
| --- | --- | --- | --- |
| `产品基本信息.产品名称` | `required` | `{}` | 产品名称为必填项。 |

### 4.2 枚举值

| 字段路径 | operator | 参数(JSON) | 具体规则 |
| --- | --- | --- | --- |
| `产品基本信息.是否涉及关联交易` | `enum` | `{"values":["是","否"]}` | 是否涉及关联交易仅可填写“是”或“否”。 |

### 4.3 文本长度

| 字段路径 | operator | 参数(JSON) | 具体规则 |
| --- | --- | --- | --- |
| `产品基本信息.产品名称` | `max_length` | `{"max_length":50}` | 产品名称不得超过 50 个字符。 |

### 4.4 数值精度

| 字段路径 | operator | 参数(JSON) | 具体规则 |
| --- | --- | --- | --- |
| `交易结构.发行规模` | `number_precision` | `{"scale":2}` | 发行规模应为数值，最多保留两位小数。 |

### 4.5 日期格式和期限

建议拆成两条规则：先校验日期格式，再校验日期范围。

| 字段路径 | operator | 参数(JSON) | 具体规则 |
| --- | --- | --- | --- |
| `产品基本信息.成立日期` | `date_format` | `{}` | 成立日期应为 YYYY-MM-DD 格式。 |
| `产品基本信息.成立日期` | `date_range` | `{"min":"today","max_days":365}` | 成立日期不得早于当前日期，且不得晚于一年后。 |

### 4.6 编码格式

| 字段路径 | operator | 参数(JSON) | 具体规则 |
| --- | --- | --- | --- |
| `产品基本信息.产品编码` | `regex_match` | `{"pattern":"[A-Z]{2}\\d{6}"}` | 产品编码应为两位大写字母加六位数字。 |

Excel 中 JSON 的正则表达式需要保留双反斜杠，例如 `\\d`。

### 4.7 两字段数值比较

| 字段路径 | operator | 参数(JSON) | 具体规则 |
| --- | --- | --- | --- |
| `交易结构.次级受益权规模` | `compare_fields` | `{"right_field":"发行规模"}` | 次级受益权规模不得大于发行规模。 |

`compare_fields` 固定判断“当前字段不得大于 `right_field`”。两个字段必须都是数值。

### 4.8 条件必填

当“是否涉及关联交易”为“是”时，“关联方名称”必须填写：

| 字段路径 | operator | 参数(JSON) | 具体规则 |
| --- | --- | --- | --- |
| `关联交易信息.关联方名称` | `conditional_compare` | 见下方 JSON | 当涉及关联交易时，应填写关联方名称。 |

```json
{
  "trigger": {
    "field": "是否涉及关联交易",
    "op": "equals",
    "value": "是"
  },
  "target": {
    "field": "关联方名称",
    "op": "required"
  }
}
```

### 4.9 材料必交

| 规则名称/要素名 | operator | 参数(JSON) | 具体规则 |
| --- | --- | --- | --- |
| 信托合同 | `material_required` | `{"material_label":"信托合同","file_ext":[".pdf",".docx"]}` | 应提交信托合同。 |

材料类规则无需填写 `字段路径`。如需“满足条件时才必须上传材料”，使用 `conditional_material_required`，并填写 `触发条件`，例如 `是否涉及关联交易=是`。

## 5. 参数(JSON)填写规范

1. 必须是 JSON 对象，使用英文双引号。
2. 参数名称使用英文，例如 `values`、`max_length`、`right_field`。
3. 数字不加引号，例如 `{"max_length":50}`，不要写成 `{"max_length":"50"}`。
4. 字符串和数组成员必须加双引号。
5. 空参数填写 `{}`，不要填写“无”“-”或空格。

正确：

```json
{"values":["是","否"]}
```

错误：

```text
values=是、否
```

```json
["是","否"]
```

各 operator 的完整参数要求见下文第 6 节。

## 6. 全部 operator 的填写规则和参数字典

| 需要校验的内容 | 使用的 operator | 主要参数 |
| --- | --- | --- |
| 字段不能为空 | `required` | 无 |
| 字段只能选指定值 | `enum` | `values` |
| 子字段必须属于父字段对应值 | `dependent_enum` | `parent_field`、`child_field`、`mapping` |
| 文本不超过指定字数 | `max_length` | `max_length` |
| 是数值且限制小数位 | `number_precision` | `scale` |
| 日期格式 | `date_format` | 无 |
| 日期早晚范围 | `date_range` | `min`、`max_days` |
| 编码/文本正则格式 | `regex_match` | `pattern` |
| 序号从 1 连续递增 | `sequence_contiguous` | 无 |
| 左字段不得大于右字段 | `compare_fields` | `right_field` |
| 当前模板与上一次登记模板一致 | `cross_template_equal` | `current_field`、`baseline_field` |
| 在条件下校验字段 | `conditional_compare` | `target`，可选 `trigger` |
| 必须上传某材料 | `material_required` | `material_label`，可选 `file_ext` |
| 条件下必须上传某材料 | `conditional_material_required` | 同上，并填 `触发条件` |

### 6.1 无参数或可填 `{}` 的 operator

| operator | 参数(JSON) | 实际执行逻辑 | 填写要点 |
| --- | --- | --- | --- |
| `required` | `{}` | 字段为空时产生问题。表级规则可通过 `要素分类/表名` 配合 `规则对象=表` 检查整张表。 | 字段规则必须填写准确的 `字段路径`。 |
| `date_format` | `{}` | 字段不是有效的 `YYYY-MM-DD` 时产生问题。 | 不接受 `YYYY/MM/DD`、中文日期等格式。 |
| `sequence_contiguous` | `{}` | 收集同一字段的多个值，要求为从 1 开始的连续整数。 | 用于重复表的序号字段；路径应指向序号列。 |

### 6.2 枚举、长度、数值和日期类 operator

#### `enum`

`values` 必须是允许值数组。未填写 `values` 时规则会跳过并记录配置告警，不会转入 AI 兜底。

```json
{"values":["是","否"]}
```

复选字段可增加 `multi_select:true`。多个已选值可用顿号、逗号、分号、斜杠或换行分隔。

```json
{"values":["现金管理","资产证券化","家族信托"],"multi_select":true}
```

#### `dependent_enum`

用于省市、一级分类与二级分类等联动枚举。重复表中会按同一行匹配父字段和子字段，不会串行比对其他记录。

```json
{
  "parent_field":"推介地1",
  "child_field":"推介地2",
  "mapping":{
    "安徽省":["合肥市","芜湖市"],
    "江苏省":["南京市","苏州市"]
  }
}
```

三个参数均为必填；映射为空或任一映射值不是非空数组时，规则文件不能导入。

#### `max_length`

`max_length` 必须是整数。未填或填写成字符串时不做长度限制。

```json
{"max_length":50}
```

#### `number_precision`

该 operator 总会检查字段是否为数值；`scale` 用于限制最大的小数位数，必须是整数。

```json
{"scale":2}
```

不填写 `scale` 时，仅校验“是否为数值”，不限制小数位数。

#### `date_range`

日期字段必须先符合 `YYYY-MM-DD`。目前支持的范围参数如下：

| 参数 | 类型 | 作用 |
| --- | --- | --- |
| `min` | 字符串 | 目前仅支持 `"today"`，表示日期不得早于系统当天。 |
| `max_days` | 整数 | 日期不得晚于系统当天起的指定天数。 |

```json
{"min":"today","max_days":365}
```

建议对同一字段另配一条 `date_format`。`date_range` 遇到格式错误只会跳过范围判断，因此不会替代日期格式校验。

#### `regex_match`

`pattern` 是 Python 正则表达式，系统要求整个字段值匹配。未填写 `pattern` 时不做格式校验。

```json
{"pattern":"[A-Z]{2}\\d{6}"}
```

该示例允许 `AB123456`。Excel 单元格中应保留 JSON 中的双反斜杠 `\\d`。

### 6.3 字段比较和跨模板比对

#### `compare_fields`

当前字段是左值，`right_field` 是右值；系统固定检查“左值不得大于右值”。两个字段必须都能解析为数值。

```json
{"right_field":"发行规模"}
```

`right_field` 可填写字段名或完整字段路径。缺少该参数时规则转 AI 兜底；找不到右侧字段或任一字段不是数值时，脚本不会产生问题。

#### `cross_template_equal`

用于校验当前申报模板与“上一次登记申报模板”中的字段是否一致。

```json
{
  "current_field":"产品基本信息.产品名称",
  "baseline_field":"产品基本信息.产品名称"
}
```

两个参数均可省略，此时系统使用本行的 `字段路径`。审核材料必须包含“上一次登记申报模板”；缺少该材料时，本规则会跳过并记录日志，不会自动判定材料有误。

### 6.4 `conditional_compare`：条件字段校验

用于“当 A 满足条件时，B 必填、等于某值、在某范围内或与另一字段比较”。`参数(JSON)` 必须有 `target` 对象，并且 `target` 至少包含 `field`、`op`；否则规则转 AI 兜底。

```json
{
  "trigger": {
    "field": "是否涉及关联交易",
    "op": "equals",
    "value": "是"
  },
  "target": {
    "field": "关联方名称",
    "op": "required"
  }
}
```

`trigger` 为可选的条件对象，可使用以下 `op`：`equals`、`not_equals`、`contains`、`not_contains`、`in`、`contains_any`、`contains_all`、`not_contains_all`、`not_blank`、`blank`。

`target.op` 及所需参数如下：

| target.op | 需要的参数 | 作用 |
| --- | --- | --- |
| `required` | 无 | 目标字段不能为空。 |
| `equals`、`not_equals`、`contains`、`not_contains` | `value` | 与单一值比较。 |
| `in`、`contains_any`、`contains_all`、`not_contains_all` | `values` 数组 | 与多个值比较。 |
| `lte_field`、`gte_field` | `other_field` 或 `right_field` | 与另一数值字段比较。 |
| `range` | `min`、`max`（可任选一项） | 校验数值上下限。 |

数值比较示例：

```json
{
  "trigger":{"field":"是否分层","op":"equals","value":"是"},
  "target":{"field":"次级受益权规模","op":"lte_field","other_field":"发行规模"}
}
```

同一重复表中的字段，系统会优先在同一行内查找触发字段和比较字段。

### 6.5 材料类 operator

#### `material_required`

用于检查是否上传或识别到某材料，无需填写 `字段路径`。建议填写 `material_label`；`file_ext` 为可选的允许扩展名数组。

```json
{"material_label":"信托合同","file_ext":[".pdf",".docx"]}
```

未填写 `material_label` 时，系统依次使用 `规则名称/要素名`、字段名作为材料名称。

#### `conditional_material_required`

参数与 `material_required` 完全相同。是否执行通常通过 sheet 中的 `触发条件` 列控制：

| 触发条件 | operator | 参数(JSON) |
| --- | --- | --- |
| `是否涉及关联交易=是` | `conditional_material_required` | `{"material_label":"关联交易说明"}` |

未填写 `触发条件` 时，它等同于无条件的材料必交规则。

### 6.6 不支持的 operator

不要填写 `custom_condition`、`format_check` 或任何自定义 operator。这些规则不会按确定性脚本执行，会转入 AI 兜底审核。

## 7. 上传和启用步骤

1. 在网页中切换到适用的登记流程。
2. 在“上传规则版本”区域上传 `.xlsx` 或 `.xlsm` 文件。
3. 上传成功后，在规则版本列表中点击“启用该版本”。
4. 若本次只想使用上传规则，关闭“启用内置规则”。内置规则默认开启。
5. 上传申报材料后发起审核，查看进度日志是否显示“脚本审核完成”。

上传文件可以只包含 `脚本审核规则` sheet；但使用系统提供的双 sheet 模板时，可以保留空的 `AI审核规则` sheet。

## 8. 常见问题

### 上传成功，但没有发现问题

按以下顺序检查：

1. `启用状态` 是否填了 `否`、`false` 或 `0`。
2. `字段路径` 是否与申报模板实际字段一致。
3. `operator` 是否正确，参数 JSON 是否完整。
4. `触发条件` 是否实际满足。
5. 字段值是否为空；除 `required` 外，多数 operator 会跳过空值。
6. `cross_template_equal` 是否上传了“上一次登记申报模板”。

### 上传时报参数 JSON 解析失败

检查是否使用英文双引号、花括号是否成对、数组中的值是否加双引号。不要把 Excel 公式、中文引号或说明文字混入 JSON 单元格。

### 为什么规则进入 AI 兜底

常见原因包括：不支持的 `operator`、`compare_fields` 缺少 `right_field`、`conditional_compare` 缺少完整 `target`。AI 兜底仅在材料事实足够明确时输出问题，不会因为脚本参数不足直接认定申报材料错误。

### 规则写 AI 还是脚本

适合脚本：字段必填、固定枚举、长度、日期格式、数值精度、明确字段比较、材料是否提交。

适合 AI：跨材料语义一致性、文字表述是否充分、文件内容是否完整、复杂业务判断、版式或首页显著位置要求。

## 9. 上传前检查清单

1. sheet 名为 `脚本审核规则`，未修改表头。
2. 每条规则都有唯一的 `规则ID`、完整的 `具体规则` 和有效 `operator`。
3. 字段类规则填写了准确的 `字段路径`。
4. `参数(JSON)` 是合法 JSON 对象，且参数与 operator 匹配。
5. 条件规则的触发条件和目标字段都已填写。
6. 不需要执行的规则才填写 `启用状态=否`。
7. 已避免与当前流程的内置规则或 AI sheet 中的 ID 重复。
8. 已在网页中启用上传的规则版本；如需仅用上传规则，已关闭内置规则。
